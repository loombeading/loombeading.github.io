manifesto

会話の外に、仕事を置く。

not chat

エージェントへの依頼は会話に流れ、会話は消える。誰が何を持っているか、どこで止まっているか、なぜそう決めたか。どれも文脈の中にだけあり、セッションが閉じた瞬間に孤児になる。

a dependency graph

Loom は仕事を Bead（粒）として格子に打ち込む。経糸（依存）が段の順序を決め、閉じると締まり、締まると次が開く。止まった段は Gate として人を呼び、決まった事実だけを残す。

Beads, not strings

Bead は状態を持って残る。エージェントがそのまま読んで動ける。

One shuttle

claim は排他だ。何人来ても、同じ段を通すのはひとりだけ。

More like a ledger

来歴は消えない。閉じた Bead も、理由ごと残る。

vocabulary

はじめから、織りの動詞だった。

lm ready
いま開口している段を見る。
lm ready --claim
杼を取る。杼はひとつしかない。
lm blocked
上の段が塞がっていれば、通せない。
lm dep add
経糸を張る。段の順序が決まる。
lm gate create
自分では決めず、手を止めて、人を呼ぶ。
lm close
筬で打ち込む。締まると、次が開く。
lm show
一段の来歴を読み返す。いつ・誰が・なぜ。

ready・blocked・close・claim は、はじめから織りの動詞だった。閉じることが締めることであり、締まると次が開く。それは比喩ではなく、依存関係の実装そのものである。

faq

よくある問い。

Loom とは？ lm とは？

Loom はエージェントと人が同じ仕事を進めるための依存グラフで、lm はその CLI だ。仕事を Bead として登録し、依存と Gate から「いま着手できるもの」を返す。

ただの Issue トラッカーでは？

読み手がエージェントである点が違う。出力は Markdown、機械向けには lm export の JSONL。実行中に入力を待たないので、エージェントが固まらない。

ネットワークに出ないのは本当？

実行時に外部へ接続しない。状態は SQLite のローカルファイルひとつで、持ち運べて、消せる。

二人が同じものに着手したら？

lm ready --claim は排他だ。杼はひとつしかないので、同じ段を二人が通すことはない。

人の判断が要るときは？

lm gate create で段を止め、人を呼ぶ。待った時間ではなく、決まった理由が来歴に残る。
